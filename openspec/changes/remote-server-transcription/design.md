## Context

状态：2026-10-22 已实现并完成目标 Windows/WSL2 原生 GPU 功能/资源验收，任务 42/44；准确率语料与手机端到端验收未完成。下文初始选型背景保留提案时信息。

用户目标：手机仅负责采集，远端服务器用更好的模型转录；服务端此前不存在，包含在本次交付范围内。优先解决准确率，实时字幕没有被确认为首版要求。按单人或小规模自建单机部署设计。用户已确认现有硬件：RTX 3080 Ti 12 GB 显存、8 核 CPU、32 GB 内存；设计以该机器为目标，不要求升级或租用 24 GB GPU。

现状：Android 前台服务持有麦克风和权威录音，Flutter/Riverpod 协调转录，Drift 持久化任务和转录版本。本地双阶段转录有大量未提交改动。README、release manifest 和 policy tests 仍要求完全离线，需要明确迁移。现有 StreamingRemote* 类型不能据名称认定为网络服务实现，网络协议应独立设计。

## Goals / Non-Goals

**Goals:**

- 交付手机采集 → 可恢复上传 → 服务端异步识别 → 手机查看/编辑/导出的闭环。
- 手机录音不受网络、服务端故障、模型加载或 GPU 队列影响。
- 新远端录音无需安装手机识别模型；历史录音、转录和人工修改可继续访问。
- 服务端提供可部署产物、鉴权、持久化存储、失败恢复、模型适配和评测入口。

**Non-Goals:**

- 首版不承诺实时字幕、跨设备账号同步、多机 GPU 调度或自动会议总结。
- 不把大模型文本润色作为原始识别结果；说话人分离作为独立可选能力，不假定 ASR 自带。

## Decisions

### 1. 模型先评测，再冻结默认配置

| 路线 | 适用性与取舍 | 本次定位 |
| --- | --- | --- |
| Qwen3-ASR-1.7B + Qwen3-ForcedAligner-0.6B | 官方提供中文/英文/方言识别、离线与流式入口；时间戳由对齐模型提供。流式入口目前不返回时间戳，不能直接满足最终稿时间轴 | 有 GPU 时优先评测，候选默认 |
| faster-whisper + multilingual large-v3 | CTranslate2 推理、CPU/GPU 和量化选项、分段输出；可作为现有 Whisper 路线的服务器质量对照 | 第二候选与可复现基线 |
| FunASR：Fun-ASR-Nano / SenseVoice-Small | Nano 适合中文、英文和方言评测；SenseVoice 有 CPU 路线。VAD、时间戳和说话人能力依模型及流水线单独配置 | 中文备选；无 GPU 时优先试 SenseVoice |
| 自建业务服务 + 云端 ASR API | 无需管理 GPU，但有供应商费用、可用区、音频外传和输出协议限制 | 若不准备 GPU，可选部署方式，不默认启用 |

推荐依据是官方能力与系统适配性，不能视为本项目准确率结论。Qwen 发布者报告中的优势需要用实际会议录音复核。保留一个 ASR adapter 接口；首版不要求同时生产运行所有候选。

首个验证配置采用 Python qwen-asr transformers 后端、单 worker/单并发，先验证输出和对齐；有吞吐需求再评测 vLLM，避免把新服务与高并发运行时调优绑在一起。

目标机器运行配置：Qwen3-ASR-1.7B 使用 transformers 后端、16 位权重、`max_inference_batch_size=1`，GPU 同时只运行一个任务。先采用约 30 秒的有界音频块作为验证起点，结合静音切分与边界重叠，实测后调整；不将整场会议一次送入 GPU。CPU 负责解码、重采样、摘要和上传服务，线程数可配置，避免解码器与推理线程耗尽全部 CPU。

1.7B 模型按 16 位参数粗估权重约 3.4 GB，但这不包含激活、缓存、音频编码器中间结果及运行时分配，不能作为实际峰值显存结论。12 GB 值得优先验证此配置，无需先降为 0.6B 或购置新显卡；能否稳定运行仍以目标机器实测为准。

为控制峰值显存，ASR 与 ForcedAligner 在独立子进程阶段顺序运行，前一进程退出后再启动后一阶段；不同时常驻两个模型。多次模型加载的额外时间是首版为显存余量付出的代价。评测时记录实际可用显存，并为桌面占用留余量。显存不足先缩短输入块并保持单批；必要时提供用户可选的 Qwen3-ASR-0.6B 或 faster-whisper large-v3 `int8_float16` 配置，记录实际模型，不能静默改变识别配置。首版不引入 vLLM 显存池或多 worker 并发。

### 2. 手机持有原始音频，首版结束后上传

```mermaid
flowchart LR
  A[Android 录音服务] --> B[本地原始分段与 manifest]
  B --> C[持久化上传任务]
  C -->|HTTPS 分块续传| D[服务端 API]
  D --> E[音频文件与任务数据库]
  E --> F[独立模型 worker]
  F --> G[带时间戳的版本化结果]
  G -->|状态查询与结果下载| H[手机 Drift 与转录界面]
```

录音完成且 manifest 验证通过后入队上传。网络请求不进入录音回调或磁盘提交路径。上传直接读取已提交的音频文件，避免整段音频进入 Dart 内存或复制成多个巨大文件。服务器负责解码、重采样和模型输入转换。

首版不上传仍在写入的分段。后续若需要实时文本，可上传已提交分段或另设有界实时流；最终稿仍使用完整权威音频重跑，不能把分块草稿拼接当成完整转录。

### 3. 单机服务，API 与模型 worker 分离

建议新增 `server/`：Python/FastAPI API 进程、独立 worker 进程、SQLite WAL 任务库和挂载卷上的音频/结果文件。API 只处理元数据、上传和查询；worker 调度独立子进程按阶段加载固定模型。Docker Compose 统一启动和挂载，反向代理终止 TLS。部署文档以 Linux/NVIDIA 容器环境为基准；Windows 用户使用 WSL2 路线并单独验证 GPU 可见性，不能声称未经验证的平台已通过。

单机首版不引入 Redis、Celery、PostgreSQL 或对象存储。SQLite 使用短事务及原子条件更新领取任务，带租约、心跳、attempt generation 和过期恢复。推理在事务外进行；旧 worker 不得提交新 attempt 的结果。未来多机扩展时替换任务库和文件存储，不改变手机客户端契约。

模型权重预下载并固定 revision；运行配置记录 runtime、模型 revision、解码参数、分块策略、对齐模型和协议版本。readiness 在权重和依赖可用后才通过；API liveness 与 GPU readiness 分开。

### 4. 可恢复协议

建议 API 轮廓，详细字段在获批后的实施计划中冻结：

- `POST /v1/uploads`：声明 manifest、音频大小和摘要，返回服务端 uploadId 与建议 chunkBytes。
- `GET /v1/uploads/{id}`：读取各文件已确认偏移。
- `PUT /v1/uploads/{id}/files/{fileId}`：按偏移上传二进制块；同一偏移重试相同内容幂等，不同内容拒绝。
- `POST /v1/uploads/{id}/complete`：校验长度、摘要、manifest 顺序和可解码性后原子封存。
- `POST /v1/transcriptions`：已封存 uploadId、客户端幂等键和模型配置；返回稳定 jobId。
- `GET /v1/transcriptions/{id}` 与 `/result`：查询状态或下载版本化分段结果。
- `DELETE /v1/transcriptions/{id}`：幂等取消并清理其任务产物；与 worker 提交采用 generation 校验。

jobId 和 uploadId 持久化到手机；响应丢失时使用同一幂等键恢复。相同 key 不同请求体必须报冲突。服务端校验租户所有权、配额和文件路径，首版采用管理员发放的可撤销客户端 token；第三方 API key 只留服务端。TLS 用于非本机连接，不把裸模型服务端口暴露给手机。

### 5. 状态与结果

手机：等待上传 → 上传中 → 等待服务端 → 转录中 → 完成，另有等待网络、失败可重试、取消。上传进度以服务端已确认字节为准。Android 后台上传由持久化平台任务承接，不依赖 Flutter 页面常驻；前台同步只是同一持久化状态的观察者。

服务端：queued → running → succeeded / failed / cancelled。超过租约的运行任务可重新领取；确定性错误、鉴权错误和 OOM 不能无限重试。用户重跑创建新 run，网络重试复用同一 job。

结果包括 audioManifestDigest、request/run identity、模型来源、语言和毫秒级片段时间戳。所有分段映射回暂停不计时的录音媒体时间轴。长录音由服务端按静音边界和模型输入预算切块；记录原始 offset，边界重叠需对齐去重，超限语音再强制分块。对齐模型每块输入受其上限约束（Qwen 官方说明最多 5 分钟），不一次对齐数小时录音。

手机校验结果身份、摘要、schema 和时间边界，在事务中写入新转录版本。自动拉取可恢复；已有人工编辑绝不被覆盖。说话人标签未运行分离时返回未知，不按 ASR 文本猜测。

### 6. 数据保留与故障边界

默认成功或终态失败后 24 小时清理服务器音频及结果；未完成上传自最后活动起 24 小时过期。客户端未下载前必须显示过期时间，过期后可由本地原音重新提交。此默认值可配置，并在客户端展示实际策略。

取消先标记终态使结果不可提交，再由 worker/清理器删除受控文件。服务端删除失败可重试；手机原始音频不因服务器清理而删除。日志不记录音频、转录正文、token 或签名 URL。

## Risks / Trade-offs

- [采集本身丢音或远场信噪比低] → 保留原音实听和输入健康检查；迁移算力不能修复缺失的声音。
- [长音频遗漏、重复与静音幻觉] → 语音检测、分块边界评测、静音样本和覆盖检查，不能用语言模型补写缺失内容。
- [后台进程被杀或断网] → 持久化平台上传、服务端确认偏移、任务幂等与重启恢复测试。
- [更好的模型并不改善目标会议] → 用同一批有人工参考的真实音频测 CER/WER、专名错误、漏句、耗时和峰值内存，不只看单个演示。
- [既有离线要求发生改变] → 新设置明确远端目的地与上传行为，旧会议不自动上传；同步修改政策文档和 release gates。

## Implementation clarifications (2026-10-21)

源码核查发现 `TranscriptRuns` 对 bundled model catalog 有强制复合外键，直接复用会把远端权重错误表示为手机内已安装模型。远端任务与结果采用新增的 `RemoteTranscriptionTasks`、`RemoteTranscriptVersions` 表，结果保存实际远端模型来源和人工编辑，会议详情提供独立的远端版本入口；旧本地版本和模型目录不改写。远端文本/JSON/字幕导出及备份恢复必须覆盖新增表，不能只存在服务器上。

Android 持久化 JobScheduler 只作为网络可用时的唤醒缓存，任务及请求身份以应用 Drift 数据库为准；原生上传 repository 与 Dart repository 使用同一新增表的明确状态转换。凭据保存在 Android Keystore 加密的私有文件中，数据库只存凭据引用。原生后台工作与数据库启动迁移使用同一文件锁隔离，避免迁移快照期间存在后台写者。协议/结果校验与幂等写入由仓库承担，界面只观察。

服务器阶段补充：有界重叠窗口按媒体中点归属去重；识别输出与对齐输出逐块核对覆盖，非空文本不能被空对齐结果吞掉。实际解码样本量必须符合 manifest 声明，不能只信容器 duration。模型通过准备命令下载指定完整 revision 并生成逐文件摘要，执行前核验。GPU 锁描述符由阶段子进程继承，Linux/WSL2 还设置父进程死亡终止信号，确保父 worker 崩溃不能放行仍占 GPU 的旧阶段。

后台 SQLite 兼容性补充：现有表启用了 STRICT，最低支持的旧 Android 自带 SQLite 版本不足，因此原生后台仓库必须使用固定的 `androidx.sqlite:sqlite-bundled:2.6.2` 驱动，而非 `android.database.sqlite.SQLiteDatabase`。该连接只读写同一任务/结果表，通过同一 WAL 协议和迁移文件锁与 Drift 协作；不能让系统旧 SQLite 尝试升级或重建文件。

### 实现审查补充：恢复身份与前台抢占

远端版本表保存显式 sourceMeetingId/sourceRunId，普通导入为空时绑定当前记录；备份恢复在重映射本地 ID 前校验原始 JSON 与源记录身份、任务摘要及 schema，并固定源身份。恢复副本保留原始 JSON 不变，后续再次恢复仍按源身份校验。无效或跨会议结果使恢复事务失败，不导入半份数据。

前台数据库 prepare 先暂停后台调度、主动断开已注册的网络连接，再等待后台关闭数据库并释放文件锁；resume 后重新调度。不得让前台启动等待整场上传。服务端提交恢复标记在传输错误后必须保留，直至拿到 jobId 或取消确认。能力读取保留策略，上传/任务响应中的实际过期时刻先持久化，再获取结果，并展示给用户。

### 镜像构建验收补充

镜像以 Linux/amd64 构建并独立验证非 root API、持久卷与容器重启。受管理的 TLS 代理环境可通过可选 BuildKit CA secret 完成正常证书校验；证书不写入运行镜像，不关闭校验。CUDA 大依赖的下载超时与并发作为构建参数可调。代理通过临时 localhost CA 做容器级 HTTPS 验证；这不替代手机信任链、公共证书签发与目标 GPU 推理验收。

### 目标 GPU 验证发现的兼容性补充（2026-10-22）

实际 Qwen ForcedAligner 对部分汉字输出相同的起止时间。禁止删除这些字或人为添加毫秒时长；在同一块内把零时长词与相邻的正时长词合并，采用已有模型时间边界的包络，保留文字顺序及标点。前导零时长词并入后续正时长词，其他零时长词并入前一片段；整块没有正时长锚点、倒序或越界时间仍失败。结果来源记录该时间归并策略。此策略只改变片段粒度，不宣称逐字精度。

锁定的 faster-whisper 1.2.1 通过 `metadata_errors` 调用 PyAV，而 PyAV 19 已删除该参数。GPU 可选依赖约束 `av<19`，保留锁定文件，并用真实解码测试覆盖该运行时兼容边界；模型身份和精度不变。

实际 600 秒样本揭示重叠窗口在同一边界给出不同词语是正常 ASR 候选分歧；把任何分歧作为整场失败不满足长录音要求。对剩余时间相交的完整候选组，选择距源窗口边缘最远（组内最小 margin 最大）的一组，平分时选较早窗口；保留该组原文和原时间，不混合不同窗口的冲突词组。结果来源记录 boundaryPolicy 与 boundaryConflictGroups。仅丢弃竞争时间上的另一假设，不作文本补写或准确率保证；同块倒序、越界、全零时长等无效数据继续拒绝。

归属裁决前保留所有候选，不先按词去重。时间相交的词组成竞争组；相接且来自同一组窗口的多个竞争组一起处理，以兼容“你好/呀”和“你/好呀”等不同分词。非竞争区间保持原文与时间。只有选定完整窗口假设之后才丢弃另一副本，避免共有词先被去重、随后又随另一窗口丢弃。

## 用户追加：采集端精简与局域网 HTTP（2026-10-22）

用户要求精简手机按钮，并明确内网转录暂用 HTTP。此要求取代首版对所有非本机连接强制 TLS 的限制：HTTPS 保持系统证书与主机名校验，HTTP 仅允许标准点分十进制 RFC1918 IPv4 与 127.0.0.1；不接受公网 HTTP、HTTP 主机名、重定向或 URL 中的凭据/查询/路径。Dart 和原生共享端点测试向量。Android 显式允许 cleartext，由唯一远端传输边界在建立连接前实施地址限制；界面说明 HTTP 用于可信内网，token 鉴权、所有权及凭据安全存储继续保留。

移动端主流程为会议列表、录音、设置。远端模式去掉语言、人数、本地模型/性能测试、实时草稿及空的本地处理入口；保留录音暂停/继续/停止、标记、回放、远端状态和已有历史资料访问。服务器配置集中在设置页，保存连接不创建会议或新转录；仅绑定已经显式选择远端而等待配置的任务，备份恢复任务仍不可自动上传。默认端点/凭据引用留在 native noBackup 目录，不增数据库 schema，不把凭据加入备份。

会议详情保留一个主转录操作（进行中不重复创建），取消仅对活跃任务显示；连接设置通过设置入口访问，结果版本编辑与导出保留，导出格式收进菜单，完整模型 revision 不占据主标题。详情的底层音频分段/事件收进可展开诊断，旧本地转录入口只对有历史本地转录的会议显示。

目标服务通过 Windows 局域网地址的独立端口转发到 WSL API，仅向本地子网开放该端口，继续 token 鉴权；不变更已有 gateway 或防火墙全局策略。验证包括端点拒绝/允许、重定向不携带 token、持久配置与恢复隔离、主要页面和背景任务回归，以及可用真机的内网连接。
