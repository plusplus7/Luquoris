## Completed

- Added an injectable `ExportService` implementation and a versioned Android Storage Access Framework destination boundary. Dart never receives app-private absolute audio paths.
- Added explicit user-selected M4A, committed-segment ZIP, TXT, SRT, structured JSON, and complete meeting ZIP outputs.
- Added privacy-preserving default names in the form `Loquiris_yyyyMMdd_HHmmss` with format-specific suffixes. Meeting titles, transcript content, and speaker names are not used in proposed external filenames.
- Added deterministic TXT/SRT formatting from the current corrected transcript and JSON containing meeting metadata, authoritative segment metadata, events, bookmarks, processing state, recovery diagnostics, every retained transcript run and its model provenance, per-version language/speaker associations, and revision history.
- Added native streaming for continuous M4A and ZIP outputs. Dart supplies the exact persisted recovery plan; native code confines entries to the selected session and copies exactly each authoritative byte prefix in plan order. A complete ZIP attempts the generation-validated M4A first and explicitly discloses committed-segment fallback or partial recovery diagnostics.
- Added explicit export navigation and a bilingual, large-text-safe format picker. Every format card is exposed as an enabled, selected-state-aware, tappable semantic button; fallback and partial-audio warnings are live-region announcements.
- Added typed channel validation, picker cancellation/failure results, single-picker exclusion, bounded small-document payloads, and best-effort deletion of a partially written destination after write failure.
- Added one operation identity across Flutter, Android, and the durable Drift record. Direct SAF records retain only meeting/format/time/state/byte/failure metadata and never retain a destination URI, external display name, meeting title, transcript text, or speaker name.
- Added localized live-region phases for destination selection, writing, and finalization, determinate byte progress where size is known, and a cancellation action only while bounded writes are safely cancellable.
- Added cooperative cancellation checks before each bounded write and again before success, preventing a final-buffer cancellation race from being acknowledged and then reported as successful.
- Added controller-owned incomplete-output cleanup and explicit cleanup-refusal propagation. Startup converts process-death `pending` rows into `export_interrupted_incomplete_output_may_remain`, and reopening that meeting's export screen restores the user-visible warning from durable history.
- Defined backup format version 1 as a deterministic streaming ZIP with `manifest.json` first, canonical `payload/checksums.json` second, independent container/database schema versions, application-version provenance, an injected UTC instant, and explicit `encrypted:false` disclosure. Every remaining payload entry has a byte length and lowercase SHA-256, and the manifest hashes the exact checksum-index bytes.
- Added a WAL-safe `VACUUM INTO` snapshot and reads the eligible audio plan back from that frozen snapshot, preventing live-database changes after snapshot creation from producing mismatched metadata and media plans.
- Added an allowlist-only native collector. The only candidates are `payload/database/loquiris.sqlite`, validated native `segments.manifest` files, exact database-authorized ADTS prefixes, and the matching CRC-validated journal prefixes. Model weights, derived M4A/waveform/index artifacts, caches, temporaries, and diagnostic logs cannot enter through filesystem discovery.
- Added two-pass source hashing and second-pass length/hash verification so a source mutation while packaging fails closed. Complete archives are written to a private temporary file, file-synced, atomically moved, directory-synced, and recorded durably with private relative path, archive SHA-256, and bytes.
- Added process-death reconciliation for pending backup records and bounded startup cleanup for staging snapshots and unpublished `.zip.tmp` files without touching completed archives.
- Added hostile restore verification before mutation: supported container/schema versions, canonical checksum identity, exact allowlisted entry set, safe paths, byte lengths, SHA-256 values, CRC-valid recording manifests, meeting-derived storage keys, and exact manifest-authorized audio/journal files.
- Added semantic recording fingerprints independent of meeting IDs, staged-database migration, and a strict native recording-index versus SQLite audio-row cross-check. Any mismatch fails before a live database row or recording directory is published.
- Added complete meeting-aggregate import for meetings, audio, recovery findings, events, bookmarks, transcript/language/diarization/speaker data, revisions, processing jobs, and required model provenance. Operational export/backup rows, preferences, model weights, caches, and logs remain excluded.
- Added content-identical skip and deterministic conflict duplication. Same-ID/different-content meetings receive UUID-v5 meeting and child IDs, rewritten foreign keys and recording paths, and an active-locale restored-copy title. Repeating the archive is idempotent across locale changes or later title edits.
- Added a single Drift transaction around all imported meetings and model provenance, with native audio publication tied to restore-operation markers. Failures roll back database rows and only matching newly published audio; startup removes orphan marked directories or finalizes markers for committed database authority after process death.
- Replaced the storage/privacy placeholder with bilingual, adaptive accounting for application/models, active meetings, rebuildable cache, trash, and available device space. Android measures own-UID application/data/cache/free totals through `StorageStatsManager` on a dedicated executor; Drift supplies authoritative committed meeting and trash audio. Private-data residuals clamp at zero, model-manifest bytes remain an included explanatory detail rather than a duplicated category, and the UI exposes loading, typed failure, and retry states while explaining that bundled models cannot be individually removed.
- Added explicit rebuildable-cache cleanup over only `cacheDir/pcm`, `cacheDir/waveforms`, `cacheDir/search_indexes`, and `cacheDir/failed_jobs`. The native walker does not follow symbolic links or inspect unknown cache siblings, and cannot reach files, recordings, backups, the database, or trash. Its versioned storage-channel result exposes only deleted-file/deleted-byte counts, preserves partial counts on typed failure, runs off the platform thread, coalesces repeat taps, and refreshes accounting after every terminal result. The bilingual adaptive UI identifies the four disposable categories and the data that is preserved.
- Added an explicit Task 9.7 regression matrix. All six export formats are reopened and compared with hand-derived content; deterministic native backup writer-to-reader staging and real-Drift identical/collision restore paths remain covered; restore capacity is injected without filling a disk and rejects a valid archive before extraction when the 32 MiB reserve cannot be preserved; permanent deletion removes private authoritative audio while a separately located exported copy remains byte-identical; default names and durable export records remain free of titles, transcript text, speaker names, destination URIs, and user-edited external names.
- Kept `android:allowBackup="false"` and `android:fullBackupContent="false"`, added Android 12+ `dataExtractionRules`, and excluded all nine supported credential- and device-protected domains from both cloud backup and device-to-device transfer. The structured release privacy gate rejects missing opt-outs, backup agents, enabled foreground backup or cross-version restore, incomplete exclusion sections, duplicate/missing domain rules, and include rules. It validates the source manifest, both merged variants, and the compiled APK resource without treating Flutter's debug-only network permission as a release permission.
- Expanded `PRIVACY.md` with explicit uninstall scope: private databases, recordings, transcripts, revisions, models, caches, working data, and private backup packages are removed; documents exported or backed up through a user-selected provider remain outside application control. The documentation also records Android's manufacturer-dependent Android 12+ device-transfer limitation rather than promising behavior the platform does not guarantee.

## Unverified assumptions

- The physical-device source meeting had no transcript, so device export exercised recording-only JSON plus empty TXT/SRT entries inside the complete ZIP. Corrected multilingual TXT/SRT and populated JSON are covered by deterministic host tests, not yet by a populated real-device transcript.
- The real-device meeting used one 1:53 committed segment. Multi-segment order, partial recovery, exact-byte truncation failure, path confinement, and fallback are covered by JVM tests; a four-hour export, destination-full behavior, and interruption during a long write remain open.
- Mid-write cancellation, final-buffer races, durable progress, controller cleanup, cleanup refusal, and process-death warning restoration are covered by deterministic host tests. A manual long-write cancellation against multiple physical document providers has not yet been run.
- Restore parsing, checksum enforcement, idempotent import, collision duplication, and crash-safe private publication are covered by host/JVM tests. An end-to-end restore of a real multi-meeting archive, process kill at publication boundaries, and destination/import UX on the acceptance device remain physical validation work for Tasks 14.6 and 15.9.
- Backup archive construction is covered by deterministic host/JVM tests but has not yet been invoked and inspected on the acceptance device. Physical low-space, process-kill, and large multi-meeting backup evidence remains open for Tasks 14.6 and 15.9; Task 9.7 deliberately injected capacity instead of filling the host or device.
- Storage accounting and rebuildable-cache cleanup are covered by pure reconciliation, channel-contract, native filesystem, controller, and adaptive widget tests. The exact `StorageStatsManager` totals, cleanup counts, and copy have not yet been inspected on the acceptance device; device/OEM behavior remains a release-validation item.
- Cloud backup was disabled and uninstall behavior was verified, but an actual two-device Android migration was not performed. Android documents that some Android 12+ manufacturers may ignore `allowBackup=false` for device transfer; the explicit exclusion rules are defense in depth, not evidence that every OEM honors them.

## Risks

- Some Android document providers do not support deletion or truncation consistently. The application now exposes an explicit incomplete-output warning when cleanup is refused or a process dies, but provider-specific physical evidence remains a release-validation item.
- Small text documents are sent through the method channel with a 16 MiB aggregate bound. This is sufficient for expected four-hour transcripts but still needs long-meeting measurement before release claims.
- The system picker permits the user to replace the privacy-preserving suggested filename. This is intentional explicit user control; Loquiris does not silently derive sensitive names.
- MVP backup archives are deliberately unencrypted and must remain behind the explicit sensitive-data warning required by Task 9.5. The manifest says `encrypted:false`; no UI may imply otherwise.
- Audio finalization after a committed database transaction is best-effort by design: a surviving restore marker does not invalidate committed audio, and startup reconciliation clears it only after confirming matching database authority.
- GitNexus reports CRITICAL cumulative risk for the uncommitted phase 5–9 working tree (346 indexed symbols, 61 indexed files, and 51 affected flows). This is not a task-9.8-only score: the task-9.8 privacy-gate entry points were LOW with no direct callers or affected flows, the Android manifest remained unresolved by the index, localization was previously HIGH because it is shared broadly, and many new phase files are not yet present in the index.
- Android's backup contract is partly manufacturer-controlled. Loquiris disables cloud backup and excludes every documented app-data domain from Android 12+ cloud/device transfer, but release claims must retain the documented OEM limitation until representative physical transfer testing exists.
